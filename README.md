# Афиша для MAX

Чат-бот для мессенджера MAX: афиша фильмов и городских событий Москвы. Данные берутся из открытого API KudaGo, навигация полностью на inline-кнопках.

- Бот в MAX: `[ЗАПОЛНИТЬ: ссылка на бота]`
- Репозиторий: `[ЗАПОЛНИТЬ: URL репозитория]`

## 1. Назначение решения

Человек, который планирует досуг, открывает бота и за два-три нажатия получает список актуальных фильмов или событий города. Под каждой позицией есть кнопка-ссылка на страницу фильма или события на KudaGo (описание, трейлер, билеты). Выходить из мессенджера на поиск по сайтам не нужно.

Регистрация не нужна, персональные данные пользователей не собираются и не хранятся.

## 2. Основной пользовательский сценарий

1. Пользователь пишет боту `/start` (или нажимает «Начать»).
2. Бот показывает выбор города, нажимает «Москва».
3. Меню города: «Афиша фильмов», «События», «Открыть KudaGo», «Другой город».
4. Список с листанием: по 4 позиции на странице, кнопки «Ещё» и «Назад».
5. Кнопка с билетом под позицией открывает страницу фильма или события на KudaGo.
6. «В меню города» и «В начало» возвращают на предыдущие экраны.

## 3. Состав и архитектура

```
Пользователь ─ MAX ─ Bot API ─▶ Бот (Node.js) ─▶ KudaGo public API v1.4
                                   │
                                   └─ кэш в памяти (30 мин)
```

Бот работает по long polling и не хранит сессий: всё состояние закодировано в `payload` кнопок (например, `m:msk:2` означает афишу фильмов, Москва, страница 3). Каждое нажатие заменяет текущее сообщение новым экраном.

| Файл | Назначение |
|---|---|
| `src/index.js` | Запуск бота, обработчики `bot_started`, `/start`, нажатий кнопок и любого текста |
| `src/screens.js` | Экраны (города, меню, списки с пагинацией) и роутер `payload → экран` |
| `src/provider.js` | Клиент KudaGo: запросы, нормализация данных, кэш, таймаут, список городов |
| `src/dates.js` | Вспомогательные функции для дат в часовом поясе города (задел под сеансы, в текущих экранах не используются) |
| `src/smoke.js` | Проверка экранов без запуска бота и без токена |
| `kudago_showings.py`, `kudago_showings_1.py` | Вспомогательные скрипты для выгрузки данных KudaGo в CSV (не нужны для работы бота) |
| `movies.csv` | Пример выгрузки афиши (Санкт-Петербург), бот его не использует |

## 4. Запуск одной командой

Нужен Node.js 18 или новее. Один раз создайте файл окружения и впишите токен (см. раздел 6):

```bash
cp .env.example .env      # Windows: copy .env.example .env
```

Затем:

```bash
npm install && npm start
```

Успешный запуск: в консоли появится строка `Бот-афиша запущен`.

## 5. Требования к окружению

- Node.js 18+ (используются встроенный `fetch` и `AbortSignal.timeout`), npm
- Выход в интернет по HTTPS к `platform-api.max.ru` и `kudago.com`
- Токен бота, созданного через Master Bot в MAX
- Python 3 и пакет `requests` нужны только для необязательных скриптов выгрузки данных

## 6. Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота из Master Bot (https://max.ru/masterbot). Без него бот завершается с сообщением «Не задан BOT_TOKEN» |

Значения читаются из файла `.env` в корне проекта (пример: `.env.example`). Файл `.env` перечислен в `.gitignore`, токен в репозиторий попадать не должен.

Прочие параметры (таймаут запроса 8 с, кэш 30 минут, размер страницы 4 позиции, окно событий 14 дней) заданы константами в `src/provider.js` и `src/screens.js`.

## 7. Используемые порты

Бот **не открывает входящих портов**: он сам опрашивает Bot API (long polling). Нужны только исходящие соединения HTTPS (порт 443) к `platform-api.max.ru` и `kudago.com`.

## 8. Зависимости

Из `package.json`:

- `@maxhub/max-bot-api` ^0.3.1: SDK Bot API мессенджера MAX
- `dotenv` ^18.0.1: загрузка `.env`

Точные версии зафиксированы в `package-lock.json`.

## 9. Внешние сервисы и интеграции

| Сервис | Что используем | Аутентификация |
|---|---|---|
| MAX Bot API (`platform-api.max.ru`) | Приём событий, отправка и редактирование сообщений, inline-клавиатуры | `BOT_TOKEN` |
| KudaGo Public API v1.4 (`https://kudago.com/public-api/v1.4`) | `/movies/` (актуальные фильмы), `/events/` (события на 14 дней) | не требуется |
| Сайт KudaGo (`msk.kudago.com`) | Страницы фильмов и событий, куда ведут кнопки-ссылки | не требуется |

## 10. Работа с данными

- **Фильмы:** `GET /movies/?location=msk&actual=true&expand=genres&fields=id,title,genres,age_restriction,site_url&page_size=100`. Бот показывает название, жанры и возрастное ограничение.
- **События:** `GET /events/` на ближайшие 14 дней (`actual_since`, `actual_until`), до 100 записей. Категория подписывается по словарю (концерт, театр, выставка и т. д.).
- **Кэш:** результаты хранятся в памяти процесса 30 минут. Если API недоступен, отдаётся устаревший кэш, а при его отсутствии показывается сообщение «Сервис афиши временно недоступен».
- **Ссылки:** если у записи нет корректного `site_url`, кнопка ведёт на поиск по названию на KudaGo.
- **Персональные данные:** не собираются, база данных не используется.

## 11. Порядок работы с тестовыми данными

Готовых тестовых наборов нет: бот работает с живыми данными KudaGo, поэтому список фильмов и событий меняется со временем.

- Проверка без токена и без запуска бота: `npm run smoke`. Скрипт печатает тексты и кнопки всех экранов (города, меню, афиша, события, некорректный payload). При недоступном KudaGo экраны покажут сообщение о недоступности, а это проверка сценария ошибки.
- `movies.csv` и Python-скрипты нужны только для экспериментов с выгрузкой. Пример: `pip install requests`, затем `python kudago_showings.py --city msk --out movies.csv`. Список городов: `python kudago_showings.py --list-cities`. В самом боте эти данные не используются.

## 12. Пошаговый сценарий проверки

1. Выполните раздел 4, дождитесь строки `Бот-афиша запущен`.
2. В MAX откройте бота и нажмите «Начать» или отправьте `/start`.
3. Убедитесь, что показан выбор города с кнопкой «Москва».
4. Нажмите «Москва»: должно появиться меню «Что смотрим?» с четырьмя кнопками.
5. Нажмите «Афиша фильмов»: список из 4 фильмов с жанрами и возрастом, внизу «Страница 1 из N» и кнопка «Ещё».
6. Нажмите «Ещё»: откроется страница 2, появится «Назад». Сообщение заменяется на месте.
7. Нажмите кнопку с билетом под фильмом: откроется страница фильма на KudaGo.
8. Нажмите «В меню города», затем «События»: список событий с категорией и возрастом.
9. Нажмите «В начало»: снова выбор города.
10. Отправьте боту произвольный текст: бот вернёт выбор города.

## 13. Примеры ожидаемого поведения

Экран после `/start`:

```
🎬 Афиша

Выберите город:
[ Москва ]
```

Меню города:

```
📍 Москва

Что смотрим?
[ 🎬 Афиша фильмов ] [ 🎭 События ] [ 🌐 Открыть KudaGo ] [ ⬅️ Другой город ]
```

Афиша фильмов (названия и число страниц меняются вместе с данными KudaGo):

```
🎬 Афиша фильмов
📍 Москва

🎬 Москва слезам не верит
драма, комедия, мелодрама · 18+

🎬 Бассейн
драма, мелодрама · 16+
...
Страница 1 из 25
[ 🎟 Москва слезам не верит ] ...
[ Ещё ▶️ ]
[ ⬅️ В меню города ] [ 🏠 В начало ]
```

Если KudaGo недоступен и кэша нет:

```
⚠️ Сервис афиши временно недоступен, попробуйте позже.
```

Ошибка в обработчике не останавливает бота: пользователь получает уведомление «Что-то пошло не так, попробуйте ещё раз», ошибка пишется в консоль.

## 14. Известные ограничения

- Доступен только один город: Москва. Новый город добавляется записью в массив `CITIES` в `src/provider.js` (slug KudaGo, название, часовой пояс).
- Нет расписания сеансов и выбора кинотеатра: по данным в комментариях скриптов, `movie-showings` у KudaGo больше не отдаёт актуальные сеансы, а длительность фильма в списке не приходит.
- Билеты в боте не продаются, только переход на KudaGo.
- Нет поиска, фильтров и избранного, только листание.
- Кэш хранится в памяти: после перезапуска он пуст, первый запрос идёт в KudaGo напрямую.
- Работает один процесс. Не запускайте несколько экземпляров с одним токеном.
- Зависимость от публичного API KudaGo: при сбоях или изменении условий афиша может быть недоступна.
- Аналитика использования не собирается.

## 15. Остановка и повторный запуск

- **Остановка:** `Ctrl+C` в терминале, где запущен бот. Если процесс запущен в фоне или через менеджер процессов, остановите его штатными средствами (`kill <PID>`, `pm2 stop` и т. д.).
- **Повторный запуск:** `npm start` (зависимости уже установлены). Состояние не сохраняется, поэтому дополнительной подготовки не нужно.
- **Режим разработки:** `npm run dev` перезапускает бота при изменении файлов.
- **Если бот не отвечает:** проверьте токен в `.env` и доступ к интернету. Ошибки выводятся в консоль. При ошибке проверки сертификата (например, `UNABLE_TO_VERIFY_LEAF_SIGNATURE`) запустите бота так: `NODE_EXTRA_CA_CERTS=./russian_bundle.pem npm start` (в PowerShell: `$env:NODE_EXTRA_CA_CERTS=".\russian_bundle.pem"; npm start`). В репозитории лежит набор корневых сертификатов российского УЦ, `russian_bundle.pem`.
